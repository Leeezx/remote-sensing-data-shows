# 灌溉乡镇下钻事件与县界对齐修复设计

**日期：** 2026-07-17
**状态：** 已获方案批准，待书面规格审阅

## 1. 背景与问题

灌溉用水页面支持县级统计和乡镇级统计。乡镇模式采用两阶段交互：地图先保留全国县级导航层，用户点击一个县后加载该县的乡镇矢量，再点击乡镇查询月度和年度灌溉用水序列。

当前存在两个可以独立触发故障的根因：

1. 用户先开启县级统计、再直接切换到乡镇级统计时，县级 GeoJSON 图层没有重建。React-Leaflet 只在创建要素时执行 `onEachFeature`，不会在属性更新时重新绑定事件，因此县要素仍调用县级模式下的旧点击回调。县 ID 随后被当作乡镇 ID 请求统计序列，接口返回 404，右侧显示“暂无统计数据”，同时没有发起乡镇分片请求。
2. 当前县级 Shapefile 与乡镇源数据使用不同版本的行政区划代码。现有分片构建器只按乡镇 ID 前六位分组，没有读取当前县界。例如当前县图层中的嫩江市代码为 `231183`，乡镇源仍归在原嫩江县代码 `231121` 下，因此当前县码对应的分片不存在。

孙吴县和牙克石市具有同码分片，主要受第一个根因影响；嫩江市同时受两个根因影响。修复必须同时覆盖事件新鲜度和构建期行政区划对齐。

## 2. 目标

- 从县级统计切换到乡镇级统计后，点击任意县都执行当前乡镇模式的县级下钻逻辑。
- 第一次点击县只加载对应乡镇矢量，不请求乡镇统计序列，也不把县 ID 写成已选乡镇。
- 乡镇矢量加载后支持点击；只有点击具体乡镇才请求该乡镇的月度和年度序列。
- 乡镇分片以当前县级图层的县码发布，使嫩江市等发生撤县设市、撤县设区或更名的地区可按当前县码访问。
- 保留全国县级年平均着色、县级导航交互、按县加载的小响应方案，以及既有分片体积和要素数上限。
- 将“该县没有可用乡镇矢量”和“已选乡镇没有统计序列”区分为不同错误状态。

## 3. 非目标

- 不修改灌溉用水统计值、时间序列计算口径或图例分级算法。
- 不在浏览器一次加载全国乡镇矢量，也不改为 MVT、PMTiles 或 WebGL 渲染。
- 不维护一份长期增长的前端县码别名表，也不在每次请求时动态执行全国空间匹配。
- 不改变县级统计模式下点击县后查询县级序列的既有语义。

## 4. 总体方案

采用“前端稳定事件委托 + 构建期空间归属”的组合方案。

前端让已经创建的 Leaflet 图层始终调用最新的 React 回调，不通过强制重建 2,891 个县要素解决事件陈旧问题。数据构建阶段则把旧版乡镇要素按空间位置归属到当前县界，并以当前县码输出分片；运行时继续执行一次确定的当前县码文件查找，不增加空间计算或别名回退。

## 5. 前端事件与状态设计

### 5.1 稳定事件委托

`RegionOverlay` 为 `onRegionSelect` 保存一个随每次渲染更新的 ref。Leaflet 要素创建时只绑定一次稳定 click 处理函数，该函数在点击发生时调用 `ref.current(feature)`。

这样即使 React-Leaflet 复用原县级 GeoJSON 图层，点击也会得到当前模式的处理逻辑。该方案避免切换统计级别时销毁并重建所有县级 SVG path，同时也适用于父组件回调因所选县、请求序号或加载状态变化而更新的情况。

样式、悬停和 tooltip 行为保持不变。县级底层和乡镇明细层各自维护最新回调引用，乡镇层继续位于更高 pane，重叠区域优先命中乡镇要素。

### 5.2 两阶段选择契约

乡镇模式下的状态必须区分：

- `selectedCounty`：当前用于加载乡镇分片的县；
- `selectedTownship`：用户在已加载分片中点击的乡镇；
- `townshipVector`：最近一次成功加载的乡镇矢量；
- 分片加载状态与乡镇序列加载状态：分别维护，文案不得混用。

交互顺序如下：

1. 切换到乡镇模式时清除已选统计区域和旧序列结果，但保留县级导航层与县级着色。
2. 点击县级底层时只更新 `selectedCounty` 并请求该县分片；不得调用乡镇序列接口。
3. 分片成功后显示乡镇要素，清除上一个县的已选乡镇和序列结果，并提示已加载的乡镇数量。
4. 点击乡镇明细层时更新 `selectedTownship`，再使用乡镇自身 ID 请求月度和年度序列。
5. 快速切换县时沿用请求序号保护，过期分片或平均值响应不得覆盖最新选择。

为防止同类回归，发起乡镇序列请求前还应检查所选要素来自乡镇明细层，而不是仅依赖页面当前 `regionLevel`。

### 5.3 失败状态

- 当前县码没有可用分片或分片为空：显示“该县暂无乡镇矢量”，不显示“暂无统计数据”，也不发起乡镇序列请求。
- 分片网络或解析失败：显示乡镇矢量加载失败状态；保留县级导航层，并保留此前成功显示的乡镇层，避免地图突然清空。
- 已点击乡镇但月度或年度序列不存在：右侧显示该乡镇“暂无统计数据”。
- 切换统计级别或选择新县时，旧县/旧乡镇错误状态不得泄漏到新上下文。

## 6. 构建期行政区划对齐

### 6.1 输入与标识

乡镇分片构建器同时读取：

- 乡镇源 Shapefile：提供乡镇几何、原始乡镇 ID 和名称；
- 当前县级 Shapefile：与页面县级导航层使用同一数据源，提供当前县几何、当前六位县码和县名。

输出要素继续保留原始乡镇 ID，确保与现有 `irrigation_region_series.json` 的乡镇键匹配；只把要素的 `parentId` 和输出文件名改为其空间归属的当前县 ID/县码。县级九位内部 ID 的 `156` 前缀只用于应用标识，分片文件名统一使用六位县码。

### 6.2 空间归属算法

构建器预先计算当前县要素的包围盒并建立候选索引。对每个乡镇要素执行以下流程：

1. 从有效面积最大的主体面生成内部代表点。实现使用环的水平扫描线寻找内部区段中点，并用包含洞环的 point-in-polygon 再校验，避免普通质心落到凹多边形外部；多面与无效几何必须有单元测试。
2. 先以代表点包围盒查询候选县，再用 point-in-polygon 判定空间归属。
3. 原乡镇代码前六位只有在它对应当前县且空间判定一致时才可作为快速路径；旧代码不得直接决定输出文件名。
4. 如果代表点没有唯一命中，则把原代码、名称、代表点和候选县写入审计结果，并使正式发布失败；本次修复不新增面相交引擎或近似覆盖率猜测。
5. 无匹配、多个匹配或无效几何不能静默写入旧县码或随意选择第一个候选县。只有修正输入几何或加入带理由、可复核的显式排除后才能重新发布。

港澳台或数据源明确不覆盖的特殊区域通过显式配置的排除清单处理；排除原因和数量必须写入清单，不得与普通匹配失败混在一起。

### 6.3 输出与发布

每个当前县输出 `data/regions/township/by-county/{currentCountyCode}.geojson`。单个乡镇要素至少包含原始乡镇 `id`、`name`、`level='township'` 和当前县 `parentId`。

构建仍需满足：

- 每个分片不超过 499 个要素；
- 每个分片文件不超过 1,000,000 bytes；
- 几何简化不得产生空几何或破坏要素 ID；
- 输出先写入临时目录，通过校验后原子替换正式目录，避免部分新、部分旧的混合发布。

清单文件新增当前县源的路径或数据版本、修改时间、县要素数，以及直接匹配、空间重映射、排除、无匹配和歧义数量。正式构建只有在无未解释的匹配失败、所有要素 ID 均能命中乡镇序列、且全部分片满足大小限制时成功。

完成构建器修改后必须使用 `--force` 全量重建分片，不能只补一个嫩江市别名文件。验收至少确认当前码 `231183.geojson` 存在，且其要素保留原乡镇序列 ID；旧码文件仅在该代码仍属于当前县集合时保留。

## 7. 后端接口契约

现有按县获取乡镇分片的接口继续接收当前县 ID，并规范化为六位县码后执行确定文件查找。接口不做运行时空间匹配，也不尝试未知旧码。

- 分片存在且有效：返回 FeatureCollection、缓存头和 ETag。
- 当前县确实没有可发布乡镇：返回可区分的 404 详情，前端映射为“该县暂无乡镇矢量”。
- 分片损坏或违反清单契约：作为服务端数据错误处理，不伪装成无统计数据。

乡镇序列接口仍只接受乡镇 ID。前端状态与测试必须保证县 ID 不会进入该接口。

## 8. 数据流

```text
县级统计已开启
  → 切换乡镇统计
  → 复用县 GeoJSON，但 click 调用最新回调
  → 点击当前县
  → GET 当前县码乡镇分片
  → 显示乡镇矢量
  → 点击具体乡镇
  → GET township + 乡镇原始 ID 的月度/年度序列
  → 右侧显示统计图表
```

构建链路为：

```text
旧版乡镇源 + 当前县界
  → 内部代表点 + point-in-polygon 空间归属
  → 保留乡镇原始 ID，写入当前县 parentId
  → 以当前县码分片
  → 清单与硬门槛校验
  → 原子发布
```

## 9. 测试设计

### 9.1 前端组件与页面回归

- `RegionOverlay` 首次渲染后更换 `onRegionSelect`，不重建 GeoJSON；点击既有 Leaflet 要素必须调用新回调，旧回调不得再执行。
- 按“县级统计 → 乡镇级统计 → 点击县”操作，断言请求的是该县乡镇分片，乡镇序列接口调用次数为零，县 ID 未写入 `selectedTownship`。
- 分片成功后点击乡镇，断言 monthly/annual 均以乡镇原始 ID 请求并显示结果。
- 分片 404 显示“该县暂无乡镇矢量”，不得显示右侧“暂无统计数据”。
- 跨县快速切换时过期响应不覆盖新县；加载失败时县级底层始终保留。

### 9.2 构建器与后端回归

- 构造“乡镇旧前缀 + 当前县新代码”的小型县界/乡镇 fixture，断言输出当前县码分片、保留原乡镇 ID，并设置当前县 `parentId`。
- 覆盖直接匹配、空间重映射、凹面与洞环代表点、多面、无匹配、多匹配和显式排除分支。
- 校验清单计数、原子发布、499 要素和 1,000,000 bytes 两个门槛。
- 校验所有输出乡镇 ID 均存在于统计序列键集合中。
- 接口测试确认当前县码可返回分片，缺失分片的 404 详情可与序列 404 区分。

### 9.3 用户实例与浏览器验收

在真实页面依次验证嫩江市、孙吴县、牙克石市：

1. 先开启县级统计并等待县级图层加载；
2. 直接切换乡镇级统计；
3. 点击目标县，确认出现该县乡镇矢量且右侧不显示县名对应的“暂无统计数据”；
4. 点击一个乡镇，确认右侧显示月度和年度图表或该乡镇真实的空数据状态；
5. 点击另一个县，确认乡镇层切换而县级导航和着色仍存在。

最后运行相关前后端测试、全量测试、前端 lint、生产构建和真实浏览器交互。分片全量重建后重新统计县码覆盖差异、最大分片字节数和最大要素数，并把结果记录到验证输出。

## 10. 风险与控制

- **空间归属误判：** 通过内部代表点复核、候选县唯一命中、失败即停止发布和可审计清单控制；不允许静默猜测。
- **全量重建耗时或中断：** 使用临时目录和原子替换，旧分片在完整校验通过前继续可用。
- **事件 ref 引入类型或生命周期错误：** 用“不重建图层但回调更新”的组件测试直接覆盖库更新限制。
- **旧请求污染新选择：** 保留并扩展现有请求序号机制，分别保护分片、平均值和序列响应。
- **工作区已有大量改动：** 实施时只修改计划列出的前端叠加层、灌溉页面、分片构建器、相关接口和测试，不回退或覆盖无关文件。

## 11. 验收标准

满足以下全部条件才视为修复完成：

- 县级统计切到乡镇级统计后，既有县图层点击调用乡镇下钻逻辑，不调用旧县级选择逻辑。
- 县点击永远不会以县 ID 请求乡镇序列；乡镇点击可正常查询。
- 嫩江市使用当前县码成功返回并显示乡镇矢量；孙吴县、牙克石市同一路径正常。
- “无乡镇矢量”与“乡镇无统计数据”在接口和界面上可明确区分。
- 全国县级导航层、年平均着色、跨县切换和按县分片性能约束均未回归。
- 构建清单无未解释的无匹配或歧义要素，全部分片通过 ID、几何、要素数和文件大小校验。
- 聚焦测试、全量测试、lint、生产构建和真实浏览器验收全部通过；任何既有非阻塞警告均单独记录。
