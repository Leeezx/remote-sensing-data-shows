# 灌溉行政区统计序列缓存设计

## 目标

避免县级和乡镇级行政区统计在每次请求时重复读取并解析
`data/stats/irrigation_region_series.json`。该文件当前约 241 MB；一次区域选择会并行请求月度和年度序列，开启统计也会读取该文件以计算平均值。

## 范围

仅优化后端 `backend.data_loader.get_irrigation_region_series()` 的数据加载方式。既有 HTTP 接口、响应结构、JSON 数据结构和行政区筛选逻辑均保持不变。

## 设计

在 `backend/data_loader.py` 中为灌溉行政区序列维护进程内缓存，缓存项包含：

- 已解析的 JSON 数据；
- 源文件的修改时间（纳秒精度）和文件大小。

每次调用 `get_irrigation_region_series()` 时，先读取文件元数据：

1. 元数据与缓存一致时，直接返回已解析的数据，不再打开或解析 JSON。
2. 首次调用、缓存为空，或修改时间/大小变化时，重新加载 JSON 并更新缓存。

这样既可使同一 FastAPI 进程内的后续县级、乡镇级、月度、年度及平均值请求复用数据，也允许数据文件替换后在下一次调用自动生效，无需重启服务。

## 并发与错误处理

使用模块级互斥锁保护“检查文件状态—加载—写入缓存”这一临界区，避免多个并发请求在缓存未命中时重复解析大文件。文件不存在或 JSON 无效时沿用 `_load_json` 的现有异常语义，且不以失败结果覆盖已有的有效缓存。

## 测试

在后端测试中覆盖：

1. 首次调用解析文件，连续调用复用缓存；
2. 文件修改时间或大小变化时，下一次调用重新读取并返回新内容；
3. 缓存仅用于灌溉行政区序列，不改变通用 `_load_json` 的行为。

测试将隔离模块缓存状态，并用临时 JSON 文件替换数据路径，避免读取实际 241 MB 数据文件。

## 非目标

- 不拆分 JSON 文件；
- 不引入 Redis、数据库或跨进程共享缓存；
- 不改动前端请求数量或接口契约。

## 验收标准

在未改动数据文件时，重复行政区统计请求不再触发 JSON 解析；修改源文件后，下一次请求返回更新后的数据；现有灌溉统计接口测试继续通过。
