# 复耕潜力统一图例设计规格

## 目标

让复耕潜力评估板块的当前情景和未来情景共用同一套分类图例。不可复耕点继续使用无填充的空心圆框；一般复耕区、建议复耕区和优先复耕区使用三种固定颜色，且地图点位与右下角图例保持一致。

## 设计

### 固定分类颜色

颜色与情景解耦，由 `frontend/src/components/reclamationCanvas.ts` 统一定义：

| 分类 | 颜色 | 绘制方式 |
| --- | --- | --- |
| 不可复耕 | 不新增填充色 | 保留无填充空心框，沿用当前/未来情景的原有边框色 |
| 一般复耕区（0-5） | `#22C55E` | 绿色填充与边框 |
| 建议复耕区（5-10） | `#F59E0B` | 琥珀色填充与边框 |
| 优先复耕区（>10） | `#DC2626` | 红色填充与边框 |

三类可复耕区使用固定颜色，不再使用当前/未来情景色及透明度差异表达分类。当前/未来情景仍决定取哪一组指标、哪些点可复耕以及点位信息卡内容。

### 组件边界

- `reclamationCanvas.ts` 提供分类到颜色的单一映射，并让 `drawBasePoints` 按 `reclamationValueClass` 选择颜色。
- `ReclamationLegend.tsx` 复用该映射，保持当前/未来切换时图例分类颜色不变。
- `ReclamationPage.tsx` 和情景切换组件不改变接口，不增加数据请求。
- 不调整布局、文案、点位半径、命中检测或不可复耕点位不可点击的既有行为。

## 测试

- 纯绘制测试验证三类可复耕分类分别得到固定且互不相同的颜色。
- 绘制测试验证当前和未来情景使用同一分类颜色。
- 不可复耕样式测试继续验证 `fill` 为空、只绘制边框。
- 图例组件测试验证三种分类色块与分类文案存在，且不因情景切换改变颜色。
- 完成后运行前端测试、构建和 lint。

## 验收标准

1. 切换当前情景与未来情景时，三类可复耕点位和图例颜色保持一致。
2. 三类可复耕点位在地图上可直接通过颜色区分，而不是仅靠同色透明度区分。
3. 不可复耕点位仍为无填充空心圆框。
4. 现有点位选择、信息卡、情景切换和响应式布局行为不变。
